Claude Code から「B' 方式と idem-v2 のどちらで進めますか」と聞かれて、そもそも B' が何だったか思い出せない。そういうとき、自分の理解が足りないのかと疑いたくなりますが、私は質問の書き方のほうに原因があることが多いと思っています。

## 質問が読めなくなる理由

だいたい次の 3 つのどれかです。

1. 作業中に Claude が自分で付けた呼び名（「案 B'」「フェーズ D」など）が、説明なしで質問に出てくる
2. こちらの知識の程度を Claude が知らず、知っている前提で話が進む
3. 判断してほしいことが長い報告の途中に埋もれている

[Hacker News の Claude の冗長さを嘆くスレッド](https://news.ycombinator.com/item?id=49388752)に、1 と 3 の実例があります。ある人は「assumed-defaults research track」「validation-only build phase D」のような、何のことかわからない語が並ぶ文を挙げています。別の人は、17 ページのレポートの 14 ページ目に未回答の質問が埋まっていて、答えないでいたら Claude が勝手に答えを作って進めてしまった、と書いています。長いセッションほど呼び名が溜まって質問に混ざりやすい、というのは私の推測で、確かめてはいません。

## その場でやること: /btw で聞き返す

わからない質問が出たら、返事をする前に `/btw` で聞き返せます。[公式ドキュメント](https://code.claude.com/docs/en/interactive-mode.md)によると、`/btw` の質問と答えは会話履歴に入らず、Claude は今のセッションの内容だけから答えます（ツールは使えません）。Claude が作業している最中でも使えます。

```text
/btw さっきの質問を、このセッションを見ていない人にもわかるように言い直して。
あなたが付けた呼び名は使わずに、何を決めてほしいのか、選択肢ごとに何が起きるのかを書いて。
```

履歴に残らないので、質問の意味を確かめるやり取りが本筋の文脈を汚しません。答えを見て調べさせたくなったら、ドキュメントによれば `f` キーで会話を引き継いだ別のエージェントに任せられます。

自分の知識の程度が原因なら、それも伝えます。

```text
/btw 私は Go は詳しいけれど Temporal は 2 週間目です。その前提で、もう一度。
```

同じ聞き返しを何度もしているなら、質問の書き方の指示が足りないということです。次の節で、その指示を置きます。

## 質問の書き方を指示しておく

[公式ドキュメント](https://code.claude.com/docs/en/output-styles.md)は、プロジェクトについての知識は CLAUDE.md に、すべての応答の口調や形式は出力スタイルに、と使い分けを示しています。質問の書き方は応答の形式なので、私は出力スタイルが本筋だと思いますが、手軽さでは CLAUDE.md でも足ります。私が試した指示はこれです。

```text
ユーザーに質問するときの書き方:
1) 最初の1文で「何を決めてほしいか」を言う。
2) 作業中に自分が付けた呼び名（案A、B'、idem-v2 など）は使わず、中身で説明する。
3) 選択肢ごとに「選ぶと何が起きるか」を1行で書く。
4) 自分のおすすめと理由を1つ添える。
5) ユーザーが知らなそうな用語は1行で定義する。
全体で10行以内。
```

2 と 5 が、原因 1 と 2 に対応します。5 は Claude がユーザーの知らないことを知らないと働かないので、CLAUDE.md に自分の経験（得意な言語、触り始めたばかりの技術）を 1〜2 行書いておくと補えます。

### 試してみた

Temporal の再試行ポリシーを決めるセッションを想定した作業メモを用意しました。案 A・案 B'・独自に付けた方式名があり、判断してほしいことは 1 つ、ユーザーは Temporal 2 週間目、という設定です。これを渡して「ユーザーへの質問文を書いて」と頼み、`claude -p`（sonnet、ツールと設定ファイルは無効）で、指示なしと指示ありを 2 回ずつ実行しました。

- 指示なし 1 回目: 見出し付きで 4 ブロック、15 行ほど。呼び名は漏れていない
- 指示なし 2 回目: 質問文に「idem-v2」「案 A/案 B/B'」がそのまま出て、Temporal の設定項目名も 4 つ並んだ
- 指示あり 2 回とも: 10 行以内で、呼び名は出ず、「補償処理」のような用語に 1 行の説明が付いた

各 2 回なので、傾向が見えた程度です。メモに「ユーザーは Temporal 2 週間目」と書いてあったので、Claude がそれを知らない実際のセッションでの結果は、この実験からはわかりません。

## 冗長さが原因なら Concise スタイル

返答が長いことが主な原因なら、組み込みの `Concise` スタイルがあります。ドキュメントによると、返答の最初の 1 文に結果や答えを置き、前置き・経過の説明・最後の要約を省きます。Claude Code v2.1.237 以降が必要で、`claude --version` で確認できます。`/output-style concise` で切り替えます。説明を求めたときは全文で書く仕様なので、前提を端折る問題（原因 2）には、上の指示が別に要ります。

自分で作るなら、`~/.claude/output-styles/` に Markdown を置きます。

```markdown
---
name: Plain questions
description: 判断を求める質問を、背景なしで読める形にする
keep-coding-instructions: true
---

ユーザーに判断を求めるときは、最初の1文で決めてほしいことを書く。
作業中に自分で付けた呼び名は使わず、中身で説明する。
選択肢ごとに、選ぶと何が起きるかを1行で書き、おすすめを1つ添える。
```

`keep-coding-instructions: true` は付けておきます。ドキュメントによると、付けないカスタムスタイルでは、Claude Code 標準のコーディング用の指示（変更範囲の絞り方、検証のしかたなど）が外れます。

## 選択式の質問ツールもある

Claude Code には、選択肢付きで質問する組み込みの `AskUserQuestion` ツールがあります。[使い方を書いたブログ](https://neonwatty.com/posts/askuserquestion-claude-code-skill)の著者は、選択肢ごとに結果を書く、おすすめを先頭に置く、1 回に 1 問にする、と決めています。上の指示とほぼ同じです。コードを読めばわかることを聞くのは悪い使い方だとも書いていて、質問の数を減らすことも読みにくさの対策になります。

## 指示が守られなくなったとき

出力スタイルも CLAUDE.md も、ドキュメントの言い方では Claude が従う指示であって、強制ではありません。必ず起きてほしいことは hook の仕事だと、同じドキュメントにあります。Hacker News のスレッドには、会話が長くなると指示を忘れる、コンパクト（要約）の直後に元の冗長な書き方に戻る、という報告があります。ある人は、CLAUDE.md に「返事の各文を私の名前で始める」という無害な指示を入れておき、それが守られなくなったらセッションが長すぎる合図にしています。私は試していませんが、指示が効いているかを見分ける手段として手軽です。
